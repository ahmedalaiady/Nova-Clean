# صفحة هبوط NOVA CLEAN 🌿 (نسخة الصفحة الواحدة المضغوطة)

صفحة هبوط تسويقية مصممة بمقاس **شاشة واحدة للهاتف** (One-Screen Mobile) لمنتج تنظيف منزلي "نوفا كلين"، لحملات TikTok / Snapchat / Meta تستهدف السوق العراقي، بهدف جمع طلبات "اطلب الآن" مع الدفع عند الاستلام.

---

## 1) التصميم الحالي

الصفحة مبنية على تخطيط مضغوط من الأعلى للأسفل بدون تمرير طويل:

1. **صورة البانر التعريفي العلوي** (منيو العروض + شعار NOVA CLEAN).
2. **شبكة 2×2 لصور العروض الأربعة**.
3. **شريط ثقة مصغّر**: آمن على الأطفال / صنع في تركيا / دفع عند الاستلام.
4. **زر واتساب عائم** ثابت أسفل يسار الشاشة.

### 🖱️ آلية الطلب
- الزائر يضغط مباشرة على صورة العرض الذي يريده.
- تنفتح نافذة منبثقة (Modal) تعرض اسم وسعر العرض المختار، مع نموذج قصير:
  - الاسم الكامل *(إلزامي)*
  - رقم الهاتف *(إلزامي)*
  - المحافظة (قائمة 18 محافظة عراقية) *(إلزامي)*
  - المنطقة السكنية *(إلزامي)*
- بعد الإرسال: رسالة نجاح + زر تواصل واتساب جاهز برسالة تحتوي كل تفاصيل الطلب.

---

## 2) البنية التقنية (Backend)

الموقع يعمل على **Cloudflare Pages** مع **Pages Functions** (سيرفرلس) متصلة بقاعدة بيانات **Cloudflare D1**:

```
index.html                      الصفحة الرئيسية
css/style.css                   التصميم
js/main.js                      منطق الواجهة (فتح Modal، Validation، إرسال الطلب، إشعار تلكرام)
images/                         صور العروض
functions/tables/orders/
  ├── index.js                  GET (قائمة الطلبات مع pagination) + POST (إنشاء طلب جديد)
  └── [id].js                   GET (طلب واحد) + PUT (تحديث طلب)
wrangler.toml                   إعدادات ربط قاعدة بيانات D1
```

### نقاط الوصول (API Endpoints)

| Method | Path | الوصف |
|---|---|---|
| GET | `/tables/orders?page=&limit=` | قائمة الطلبات مع ترقيم صفحات |
| GET | `/tables/orders/:id` | جلب طلب واحد بالمعرّف |
| POST | `/tables/orders` | إنشاء طلب جديد |
| PUT | `/tables/orders/:id` | تحديث حالة/بيانات طلب |

### جدول البيانات `orders` (Cloudflare D1)

| الحقل | النوع | الوصف |
|---|---|---|
| id | text | معرف الطلب (UUID تلقائي) |
| full_name | text | الاسم الكامل للعميل |
| phone | text | رقم الهاتف |
| governorate | text | المحافظة |
| address | text | العنوان التفصيلي / المنطقة السكنية |
| offer_selected | text | العرض المختار |
| price | text | سعر العرض |
| status | text | حالة الطلب (جديد / تم التواصل / تم التوصيل / ملغي) |
| created_at | datetime | تاريخ الإنشاء |
| updated_at | datetime | تاريخ آخر تحديث |

## 3) تكامل بوت تلكرام لاستقبال الطلبات 🤖

عند إرسال أي طلب من النموذج بنجاح، يتم إرسال تفاصيل الطلب تلقائيًا إلى 3 مستخدمين على تلكرام دفعة واحدة عبر بوت `@novacleaniq_bot`، بالتوازي مع حفظ الطلب في قاعدة البيانات وتجهيز رابط واتساب.

**تفاصيل الإعداد (في `js/main.js`):**
- Bot Token محفوظ في متغير `TELEGRAM_BOT_TOKEN`
- المستخدمون المستقبلون (Chat IDs): 3 مستخدمين محفوظين في `TELEGRAM_CHAT_IDS`

⚠️ **ملاحظة معروفة:** هذا الاستدعاء يتم حاليًا من متصفح الزائر مباشرة (client-side)، لذا في حال ضعف اتصال الزائر بشبكة تلكرام (شائع أحيانًا في العراق)، قد يفشل إرسال الإشعار بصمت رغم أن الطلب يُحفظ بنجاح في قاعدة البيانات دائمًا. الحل الجذري لهذه المشكلة هو نقل استدعاء تلكرام إلى داخل `functions/tables/orders/index.js` (بعد نجاح الحفظ في D1) بدلاً من `js/main.js` — **لم يُنفَّذ بعد**، ننصح بمعالجته في تحديث لاحق لضمان وصول 100% من الإشعارات.

---

## 4) حالة البكسلات (Ad Tracking Pixels) 🧹

تمت **إزالة جميع بكسلات التتبع الإعلاني** من الكود بناءً على طلب العميل (بتاريخ هذا التحديث):
- ❌ تم حذف Meta (Facebook) Pixel بالكامل
- ❌ تم حذف Snap Pixel بالكامل
- ❌ تم حذف Snapchat Conversions API (CAPI) بالكامل

الصفحة الآن **خالية تمامًا من أي بكسل تتبع إعلاني**، وجاهزة لتركيب بكسلات جديدة عند الحاجة.

## 6) النشر (Deployment)

المشروع يُنشر عبر Cloudflare Pages باستخدام Wrangler:

```bash
npx wrangler pages deploy . --project-name novaclean --branch main
```

⚠️ **مهم:** هذا مشروع Cloudflare Pages مع Functions (وليس موقع ثابت بسيط) — يجب أن يتضمن أي نشر مجلد `functions/` و`wrangler.toml` معًا مع الملفات الثابتة، وإلا ستتعطل واجهة حفظ الطلبات (`/tables/orders`).

---

## 7) ما لم يُنفَّذ بعد (Pending) ⏳

1. **تركيب بكسل تتبع إعلاني جديد** — الكود جاهز الآن لاستقبال أي بكسل جديد بدون أي تعارض مع بكسلات سابقة.
2. **نقل إشعار تلكرام إلى السيرفر (Server-Side)** — لضمان وصول 100% من إشعارات الطلبات الجديدة بغض النظر عن جودة اتصال الزائر (انظر القسم 3 أعلاه).
3. **ربط الدومين المخصص** (اختياري، حسب رغبة العميل).
